# Problem execution v3 (manifest schema 2.0)

PROBLEM manifests have exactly schemaVersion=2.0, workload=PROBLEM, phase=COMPUTE|VERIFY, files and outputs. Files are server-owned readonly /inputs/problem.json, /inputs/plan.json, and (only VERIFY) /inputs/candidate.json with SHA-256 checks. There is no user path or generated Python import. Results use existing bounded TABLE/CHART/TEXT v2 transport, with calculation/verification JSON inside the TEXT output.

Two fresh instances of the pinned 1.2.0 Docker runtime perform computation and verification, each under existing startup-inclusive 45s default/120s max, with 10s bounded cleanup. Total default budget is 110s incl. cleanup; maximum 260s. Each phase has unchanged 256MiB, CPU/PID/network/mount/output restrictions. SymPy 1.14.0 and mpmath 1.3.0 are image-only dependencies. Allowed CAS: arithmetic, sqrt, sin/cos; one real rational-coefficient polynomial of degree 1–4, no matrices/general simplify. AST count/depth/power/plot limits and weighted numeric cost <=2048 are independent of prompt size. Explicit matrices are unsupported. Numeric values are bounded to finite magnitudes <=10^100, rational polynomial coefficients to 10^80; root residuals <=10^-7 in SI. The host binds transported table rows and chart series to the verified candidate points. The manifest and receipt schemas are normative shapes; the fixed runtime additionally checks phase-specific files and path/name/hash correspondence.

The verification receipt binds logical input hash, exact file hashes, candidate hash, number of outputs/points and absolute/relative tolerance 1e-10. Only the trusted runner's fresh controlled verifier receipt can produce CHECKED. Execution status and verification status are separate. Model plan prose and physical assumptions are not mathematical proof. Reproduction selects the saved image ID/runtime; it does not call the model. Completed attempts and inputs/plans are immutable in PostgreSQL.
